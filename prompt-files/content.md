# Content Guidelines

## Audience

The website serves:

- current ACBB members
- prospective members
- parents
- athletes
- visitors looking for competitions or club events
- people who may not be comfortable with technology


## Primary Visitor Needs

The website must make it particularly easy to:

1. Find training schedules
2. Understand which training group or category is appropriate
3. Understand how to join ACBB
4. Find required affiliation documents
5. Find upcoming competitions
6. Find ACBB-organized events
7. Contact the appropriate person


## Writing Style

Content should be:

- concise
- direct
- friendly
- practical
- easy to scan

Prefer plain language.

Avoid:

- unnecessary jargon
- long introductions
- administrative wording when simpler wording exists
- overly promotional language
- unnecessary repetition

### French usage of "handisport"

Write "handisport" as a common French noun:

- Use "Handisport" when it begins a heading, title or sentence, or when it is
  used as a standalone title, navigation label, category or UI label.
- Use "handisport" inside a sentence.

This editorial rule applies to public-facing copy. Technical identifiers,
filenames and directory names may remain lowercase or otherwise
implementation-specific.


## Content Hierarchy

Put the visitor's practical information before secondary information.

Important information should appear early.

Do not force visitors to read introductory text before reaching a
practical action.


## Progressive Disclosure

Show essential information first.

Provide additional details only when needed.

Example:

Show:

"Benjamins
Wednesday 17:30–19:00"

before displaying detailed explanations about the training group.


## Calls to Action

CTA labels should describe exactly what will happen.

Good examples:

- "Voir les horaires"
- "Télécharger le certificat médical"
- "Voir les prochaines compétitions"
- "Contacter le club"

Avoid ambiguous labels.


## Data Accuracy

Do not invent:

- schedules
- prices
- names
- contact details
- competition dates
- affiliation requirements
- clothing stock
- addresses

Use placeholders clearly marked as placeholders when real information
has not yet been supplied.

Ask the user when accurate information is required.


## Maintainability

Frequently changing information should be stored separately from UI
components whenever practical.

Avoid duplicating identical club information across multiple pages.
